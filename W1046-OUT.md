## What was implemented

1. **Registry** (`crates/chat-stasher/data/harness-registry-v1.json`): the
   `workbuddy` entry, macOS one scannable cell (`~/.workbuddy/projects/`,
   `format jsonl`, `confidence measured-locally`; the `source` line records
   that the path is also source-confirmed by the shipped app's own bundled
   constant `WORKBUDDY_PLATFORM_OWNED_PROJECT_FILE_PATTERNS` in app.asar, and
   that the sessions schema was measured locally, read-only) with
   `sql_table sessions` / `sql_id_column id` / required columns `id, transport,
   deleted_at, created_at, last_activity_at`. Windows/Linux cells declared
   with `$HOME`/`%USERPROFILE%` templates at `unascertained` — the scanner
   refuses them. `known_issue` carries the no-official-schema plus
   event-census-drift caveat; `seal_policy not-applicable` in the
   hermes/grok-bot style.

2. **Reader** (`crates/chat-stasher/src/normalize/workbuddy.rs`, new): whole-body
   walker (owns its line walk because calls pair with results by `callId`
   across lines) handling all nine shared top-level types — `session-meta`,
   `message` (user: last `<user_query>(.*?)</user_query>` span, dot-all;
   untagged user-role records are injections — counted as bookkeeping, never
   rendered as a person; assistant: `output_text` blocks concatenated with the
   reference reader's separator), `reasoning` (`rawContent` reasoning_text with
   the measured `content` fallback, rendered as thinking), `function_call` /
   `function_call_result` (paired by `callId`; a result's bytes fold into the
   call's `output_bytes`, unclosed calls keep `None`, never synthesized;
   arguments second-parsed when parseable, kept raw when torn), and
   `file-history-snapshot`, `ai-title`, `summary`, `turn-metrics` as counted
   bookkeeping (the last two were measured on the sibling CodeBuddy CLI, so the
   W1047 reuse parses them already). Unknown `type`s count as
   `unrecognized_lines` — census drift is an alarm, never a failure. Nothing
   sorts by timestamp (ms inversions were measured) — the walk is arrival
   order. Ten inline unit tests pin every arm including id hygiene
   (callId/sessionId/parentId never reach the rendered model).

3. **sqlite_probe** (`crates/chat-stasher/src/sqlite_probe.rs`): dedicated
   WorkBuddy block — `WorkBuddySessionRow` (metadata only: id, deleted,
   transport, ms time), `enumerate_workbuddy_sessions` (schema-validated,
   `SELECT id, transport, deleted_at, last_activity_at, created_at`), and
   `read_workbuddy_session` exporting either the metadata envelope
   `chat-stasher.workbuddy.session.v1` or, for `deleted_at IS NOT NULL` (any
   non-null value including the `-1` the cloud-sort index implies), a bare
   tombstone line with no row payload — the opencode tombstone shape at session
   granularity, content-hash cursors on both. Opens are strictly `mode=ro`,
   **`immutable=1` is never used for this store**; a WAL store whose `-shm` is
   absent reads through a copied db+`-wal`+`-shm` trio in a temporary directory
   (deleted on drop), so uncheckpointed WAL content still reads and no sidecar
   is created beside the user's store.

4. **Scanner** (`crates/chat-stasher/src/scanner.rs`): dedicated
   `probe_workbuddy_harness` (dispatched beside grok-bot). Walks
   `projects/<slug>/*.jsonl` only, excluding `*.file-rollback.ndjson` and
   `tool-results/` by name; duplicate copies of one session id keep the
   newest (mtime, path) and the stale ones are named in the note. Joins rows
   to transcripts by id: a paired live row emits the virtual sqlite record plus
   the transcript file record (two records, one id — the grok row/history
   shape; the state keys differ so both cursors coexist); a deleted row always
   emits its tombstone record (with the transcript beside it if still
   present); a live row without a transcript emits nothing — a recognized
   session the archive cannot write, surfaced through `archive_gaps` so
   `collect` is PARTIAL exit 3, never 0 (the unknown arm; the recognized set
   is the union of row ids and transcript ids plus unnamed rows, so orphan
   transcripts can never mask the gap); a transcript without a row archives
   on its own file-name id. A missing store keeps transcripts archival with an
   unknown count; an unreadable schema keeps transcripts and reports
   "unknown, not 0". `models.rs` gains `HarnessSource::WorkBuddy` +
   `SqliteSessionLayout::WorkBuddy`.

5. **Collect** (`crates/chat-stasher/src/collect.rs`): the `process_sqlite`
   `WorkBuddy` arm (hermes-mirror) — the row is re-read every pass, its
   metadata line re-sealed exactly once per content change, and a later
   soft-delete appends exactly one tombstone. Transcripts ride the ordinary
   append-only `process_jsonl` byte cursor unchanged.

6. **Lockstep surfaces**: fts `HARNESS_SOURCE_FORMATS` row + `export_reader`
   arm + the one-row-per-registry-harness fixture test; ui/facets classifies
   `workbuddy` under agent platforms (product-group choice; the golden captures
   were re-recorded accordingly). doctor was left untouched deliberately —
   workbuddy surfaces through the probe table exactly as grok-bot and kimi-code
   do (no footprint list covers those either).

7. **Docs and derived artifacts**: `docs/sources/workbuddy.md` (7 fixed
   headings, hand-written; generated header via the generator), support matrix
   + README short table + `docs/sources/README.md` index regenerated with the
   generators (`--apply`), `scripts/source-pages/source-pages-data-v1.json`
   `harness_surface` entry ("desktop app"), `docs-dev/output-inventory.txt`
   re-derived, citations relocated with `scripts/relocate-citations.py --old
   HEAD` (18 exact shifts, "0 need a human", every block byte-identical) and
   `docs-dev/threat-model.md` amended where its "every SQLite connection falls
   back to immutable=1" claim became stale with W1046's deliberate exception,
   then `--update` re-locked.
