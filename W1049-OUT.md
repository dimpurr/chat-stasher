## What landed (map to the ruling's three must-fixes)

1. **Identity, not path hash.** A file-backed source whose path is gone at read time is a relocation candidate, and every probe matches by session id — for codex the rollout filename's uuid rides the id the scan already minted, so no fresh id grammar exists to drift. Path sha256 stays what it always was: a digest in the report row, never a lookup key.
2. **MOVED_AWAY = collect elsewhere, not skip.** Resolution order per vanished sighting: (a) same id collected OK this pass at another root (the move happened between the scan's own root walks) ⇒ `MovedAwayNotice`, no error; (b) otherwise one fresh re-walk of THAT registry family's roots (lazy: only when a candidate exists) finds the identity ⇒ collected **in this pass** through the very same cursor-proof/seal/debt/counter machinery (extracted into `PassCollector` so no second write path can drift); a recovery whose read skips or fails records the notice instead and the next pass's ordinary scan owns the read; (c) identity in no collected root ⇒ today's `CollectError` word for word.
